# 06. Скоринг, андеррайтинг и антифрод

> Как банк технологически принимает решение: от автоматической балльной оценки до ручной проверки и защиты от мошенничества. Актуальность: 🔄 01.07.2026.

---

## 6.1. Скоринг: что это

**Скоринг** — автоматизированная оценка риска заёмщика на основе **статистической/ML-модели**, которая по набору характеристик выдаёт балл (score) — оценку вероятности дефолта (**PD**). Позволяет обрабатывать поток заявок за секунды.

**Принцип.** Модель обучается на исторических данных: у «хороших» и «плохих» заёмщиков ищут статистические различия в признаках, присваивают им веса. Новый клиент получает балл → сравнивается с **порогом отсечения (cut-off)**.

```
Заявка → признаки → модель → балл (PD) → сравнение с cut-off →
  выше порога: одобрить (условия по риску)
  пограничный: на ручной андеррайтинг
  ниже порога: отказ
```

**Типы данных (признаки) для скоринга:**
- анкетные (возраст, стаж, доход, семья, регион);
- кредитная история и рейтинг БКИ;
- поведение по счетам/картам (для действующих клиентов);
- транзакционные данные; цифровой след (устройство, канал);
- макро- и отраслевые факторы (для бизнеса).

---

## 6.2. Виды скоринга

| Вид | Когда применяется | Что оценивает |
|-----|-------------------|---------------|
| **Application scoring** | На входе, по заявке | PD нового заёмщика |
| **Behavioral scoring** | Для действующих клиентов | Поведение, для лимитов и пре-одобрений |
| **Collection scoring** | На стадии просрочки | Вероятность возврата, стратегия взыскания |
| **Fraud scoring** | На входе и в моменте | Вероятность мошенничества |
| **Response/Profit scoring** | Маркетинг | Отклик/прибыльность клиента |

---

## 6.3. Внутренние модели банков

- **Скоринговые карты (scorecards)** — классический подход (логистическая регрессия, веса признаков, интерпретируемость).
- **ML-модели** (градиентный бустинг, нейросети) — выше точность, но требуют контроля интерпретируемости и справедливости.
- **Продвинутые банки** используют **ПВР/IRB-подход** (внутренние рейтинги для расчёта капитала по требованиям Банка России) — оценки PD, LGD, EAD.
- Модели проходят **валидацию, мониторинг качества** (Gini/AUC, стабильность, PSI) и регулярное перекалибрование.

---

## 6.4. Ручной андеррайтинг

**Когда включается:**
- пограничный балл скоринга;
- крупные суммы, обеспеченные/сложные продукты;
- корпоративные заёмщики (индивидуальный анализ);
- расхождения/красные флаги в данных.

**Что делает андеррайтер:**
- верифицирует доход и занятость (звонки, документы, базы);
- перепроверяет ПДН и КИ, разбирает «спорные» записи;
- оценивает обеспечение и структуру сделки;
- проверяет комплектность и подлинность документов;
- формирует заключение и рекомендацию (одобрить/условия/отказ).

> Скоринг = скорость и объём; андеррайтинг = глубина и суждение. Хороший конвейер сочетает оба: массовые заявки — автоматом, сложные/пограничные — вручную.

---

## 6.5. Поведенческий скоринг

Оценивает **действующего** клиента по его поведению:
- своевременность платежей, утилизация лимитов, обороты, остатки;
- реакция на изменения (просрочки, досрочные погашения).

Применение: автоматическое **изменение кредитного лимита**, пре-одобренные предложения, ранняя идентификация ухудшения (early warning), выбор стратегии при просрочке.

---

## 6.6. Мошеннический скоринг и антифрод

**Fraud scoring** оценивает вероятность **мошенничества** (в отличие от кредитного риска — там оценивается способность/готовность платить добросовестного клиента).

**Виды мошенничества:**
- **Заявочный фрод:** поддельные документы, фиктивный доход/работодатель, синтетические личности.
- **Кража личности** (оформление на чужие данные) — против этого работают самозапрет и период охлаждения.
- **Первый платёж не вносится** (first-payment default) — признак фрода.
- **Социальная инженерия:** жертву под давлением мошенников заставляют взять кредит.

**Инструменты антифрода:**
| Инструмент | Что делает |
|-----------|-----------|
| Проверка документов | Подлинность паспорта (МВД), 2-НДФЛ, работодателя |
| **Device fingerprinting** | Идентификация устройства, признаки эмуляторов/подмены |
| Поведенческая биометрия | Как клиент печатает/двигает мышью/держит телефон |
| Геоданные, IP-анализ | Аномалии локации/сети |
| Проверка по базам | Чёрные списки, БКИ, межбанковские сервисы, ФССП, розыск |
| **Самозапрет (218-ФЗ)** 🔄 | Клиент сам запретил выдачу — блок на входе |
| **Период охлаждения (353-ФЗ)** 🔄 | Задержка доступа к деньгам 4/48 ч — время распознать мошенничество |
| Антифрод-скоринг в моменте | Оценка риска транзакции/выдачи в реальном времени |

**Роль службы безопасности (СБ):** проверка репутации, аффилированности, реальности бизнеса, стоп-факторов, связей с недобросовестными лицами.

---

## 6.7. Источники данных для оценки

- **БКИ** — кредитная история, рейтинг, ПДН-компоненты.
- **Госсервисы:** ФНС (доходы, статус самозанятого/ИП, задолженности), СФР/ПФР (доход, стаж), Госуслуги (СМЭВ, самозапрет), МВД (проверка паспорта, розыск), ФССП (исполнительные производства).
- **Внутренние данные банка:** обороты, транзакции, история отношений.
- **Внешние базы:** ЕГРЮЛ/ЕГРИП, арбитраж, реестры залогов/банкротств, санкционные списки.
- **Альтернативные данные:** платежи за услуги, цифровой след (с учётом закона о персональных данных 152-ФЗ и согласий).

---

## 6.8. Причины снижения кредитного рейтинга/балла

| Фактор | Почему снижает |
|--------|----------------|
| Просрочки (особенно свежие и глубокие) | Прямой сигнал риска |
| Высокий ПДН / долговая нагрузка | Мало «запаса» на новый платёж |
| Высокая утилизация карт | Признак нехватки денег |
| Частые заявки на кредит | «Кредитный голод», признак проблем |
| Короткая/пустая КИ | Нечем подтвердить дисциплину |
| Реструктуризации, каникулы, суды, банкротство | История проблем |
| Нестабильная занятость/доход | Риск потери источника погашения |
| Молодой возраст без истории | Недостаток данных |
| Стоп-факторы СБ (связи, репутация) | Повышенный риск фрода/невозврата |

> Улучшение рейтинга: гасить просрочки, снижать утилизацию карт, не подавать много заявок сразу, аккуратно обслуживать 1–2 продукта, снижать ПДН.

---

## Алгоритм принятия решения (упрощённо)
```
1. Идентификация + проверка самозапрета (стоп при активном запрете)
2. Антифрод-проверка (стоп при высоком fraud-score)
3. Кредитный скоринг → балл (PD)
4. Проверка ПДН и МПЛ
5. Пограничный результат/крупная сумма → ручной андеррайтинг
6. Обеспеченная сделка → оценка залога
7. В рамках полномочий → авторешение; иначе → кредитный комитет
8. Решение: одобрить / условия / отказ
9. Для потребкредитов — период охлаждения перед доступом к деньгам
```

## Чек-лист
- [ ] Проверен самозапрет и антифрод-сигналы
- [ ] Балл скоринга и порог отсечения
- [ ] ПДН и МПЛ учтены
- [ ] Данные верифицированы (доход, работодатель, документы)
- [ ] Пограничные/крупные — на ручной андеррайтинг
- [ ] Обеспечение оценено
- [ ] Решение в рамках полномочий/комитета

## Типичные ошибки
1. Слепое доверие скорингу без верификации данных (модель ест «мусор на входе»).
2. Игнорирование антифрод-сигналов ради плана продаж.
3. Отсутствие мониторинга и перекалибровки моделей (деградация качества).
4. Непрозрачные ML-модели без контроля справедливости/интерпретируемости.

## Рекомендации
- Сочетать скоринг (скорость) и андеррайтинг (глубина) по риск-сегментам.
- Строить early-warning на поведенческом скоринге.
- Максимально использовать самозапрет и период охлаждения как барьеры против фрода и соц. инженерии.
